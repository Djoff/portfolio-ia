Problème

Pour un vendeur d’articles d’occasion, rédiger chaque fiche produit et fixer un prix est long et répétitif.

Solution

Le vendeur envoie les photos d’un article par Telegram. Le workflow attend que tout l’album soit reçu, puis un modèle d’IA rédige la fiche produit et propose une estimation. Les prix finaux sont calculés par des règles fixes, la fiche est enregistrée en base avec un code interne, et une confirmation est renvoyée au vendeur.

Risques & garde-fous

  • Accès non autorisé → seuls les expéditeurs autorisés peuvent déclencher le workflow.
  • Prix fantaisiste de l’IA → l’IA estime, mais le prix final est calculé par des règles déterministes.
  • Erreur non vue → le vendeur reçoit une confirmation et garde la main sur la mise en vente.
  • Données résiduelles → les données temporaires de l’album sont supprimées après traitement.

Résultat

La création d’une fiche passe d’une tâche manuelle à un simple envoi de photos, avec un humain qui valide.

Ce que j'en retiens

L’IA est excellente pour décrire, moins fiable pour chiffrer : la combiner avec des règles explicites donne le meilleur des deux.

Problème

Suivre l’actualité de plusieurs sources prend du temps, et la plupart des articles ne sont pas pertinents.

Solution

Un workflow planifié lit les sources déclarées dans une base Baserow, écarte les articles déjà traités, puis demande à un modèle de langage d’analyser chaque article et de décider s’il mérite d’être lu. Les articles retenus sont regroupés dans un digest envoyé par e-mail aux destinataires configurés.

Risques & garde-fous

  • Pertinence mal jugée par l’IA → chaque article rejeté est enregistré avec la décision, ce qui permet de contrôler les choix de l’IA a posteriori.
  • Doublons et répétitions → les articles déjà envoyés sont mémorisés et filtrés avant l’analyse.
  • Silence ambigu → un digest vide est envoyé quand rien n’est retenu : on sait que la veille a tourné.
  • Modifications risquées → sources, destinataires et jour d’envoi se règlent dans la base, sans toucher au workflow.

Résultat

Une veille quotidienne qui tourne seule, avec une trace de chaque décision de l’IA.

Ce que j'en retiens

Sept versions ont été nécessaires : un agent IA se règle par itérations courtes sur de vraies données. Garder une trace des rejets est ce qui rend l’outil digne de confiance.

Supervision des automatisations

  • n8n
  • Telegram

Quand un workflow échoue, une alerte arrive aussitôt sur mon téléphone.

  1. Erreur dans un workflow
  2. ✓ Capture de l'erreur
  3. Alerte Telegram
  1. Erreur dans un workflow
  2. ✓ Capture de l'erreur
  3. Alerte Telegram

Problème

Une automatisation qui échoue en silence est pire qu’une absence d’automatisation : on croit que le travail est fait.

Solution

Un workflow d’erreur dédié est déclenché par n8n dès qu’un workflow qui y est rattaché échoue. Il envoie aussitôt une alerte sur Telegram avec le nom du workflow et l’erreur.

Risques & garde-fous

  • Échec silencieux → chaque erreur d’un workflow supervisé produit une alerte immédiate.
  • Angle mort → cette alerte ne couvre pas une panne de n8n lui-même : une surveillance externe reste à ajouter.
  • Diagnostic lent → l’alerte indique quel workflow a échoué et pourquoi.

Résultat

Les incidents sont signalés dès qu’ils surviennent, au lieu d’être découverts par hasard.

Ce que j'en retiens

La supervision n’est pas un ajout de fin de projet : c’est la première chose à mettre en place avant d’automatiser quoi que ce soit d’important.

  3. ✓ Format structuré

  7. Vidéo
  1. File de sujets
  2. Rédaction + recherche web
  3. ✓ Format structuré
  4. Document du script
  5. Fact-check
  6. ✓ Vérification des liens
  7. Vidéo

Problème

Produire régulièrement des vidéos pour plusieurs chaînes demande beaucoup de rédaction, et un texte généré par IA peut contenir des erreurs factuelles.

Solution

Les sujets sont placés dans une file d’attente (tableur). Un agent IA rédige le script complet en s’appuyant sur une recherche web, au format imposé, puis le dépose dans un document. Un second workflow relit chaque script : un agent vérifie les affirmations, liste ses sources, et chaque lien est testé avant que le script ne passe au statut « vérifié ».

Risques & garde-fous

  • Hallucinations → un fact-check séparé de la rédaction, avec sources citées pour chaque fait.
  • Sources inventées ou mortes → chaque lien cité est testé automatiquement et son état est consigné.
  • Sortie inexploitable → la réponse de l’IA doit respecter un format structuré ; en cas d’échec, une alerte est envoyée.
  • Perte de suivi → chaque sujet porte un statut (à faire, en cours, terminé, vérifié).

Résultat

Une chaîne de production où chaque script est rédigé, tracé et vérifié avant de devenir une vidéo.

Ce que j'en retiens

La première version comptait 26 nœuds et était fragile ; la version simplifiée à 17 nœuds est plus simple à maintenir. Séparer « rédiger » et « vérifier » en deux agents distincts est un principe que je réutiliserais partout.

  1. Cadrage et cahier des charges
  2. Réalisation avec un assistant IA
  3. ✓ Tests automatiques
  4. ✓ Revue de sécurité
  5. Publication en Europe

Problème

Présenter mes projets à des recruteurs sans que la vitrine elle-même devienne un risque, au moment où les failles liées à l’IA et à la chaîne logicielle se multiplient.

Solution

Un site statique bilingue généré par Hugo : chaque projet est un simple fichier texte, vérifié automatiquement avant publication. Le site est conçu et réalisé avec un assistant IA de développement, encadré par un cahier des charges, des tests et une revue de sécurité.

Risques & garde-fous

  • Chaîne d’approvisionnement logicielle → un seul outil de génération, sans dépendances npm ; versions figées et vérifiées par empreinte.
  • Injection de code (XSS) → aucun JavaScript et une politique de sécurité (CSP) qui interdit tout script.
  • Exposition de données → aucun formulaire, cookie ni traceur ; aucune donnée interne publiée, avec un contrôle automatique.
  • Code produit par l’IA → chaque étape est testée avant d’être acceptée, puis l’ensemble est relu.

Résultat

Site terminé et testé localement ; mise en ligne en Europe à venir.
